# TA-8 — AI Runtime Phase Integration, Debugging, and Validation

> **Status:** Architecture Complete
> **Authority:** Exact AI insertion into the TA-7 fixed tick, perception/decision/path-result timing, urgent interrupts, AI structural mutation rules, debug tooling requirements, and architecture-level validation expectations

## 1. Purpose

TA-8 must integrate navigation and AI into the deterministic TA-7 runtime without allowing worker timing, perception sampling, path completion, or AI container iteration to decide gameplay unpredictably.

## 2. Refined Runtime Tick

TA-8 refines the TA-7 phase slots as follows without changing TA-7 commit authority:

```text
1.  Tick Begin / Stable State Latch
2.  Apply accepted external/player gameplay intents
3.  Validate queued activation/spawn/despawn requests
4.  Advance due action/status deadlines
5.  Consume valid async navigation/AI-support results
6.  Ingest queued perception/shared-knowledge updates
7.  Run due AI high-level decisions / command-task transitions
8.  Build player + AI movement/weapon/interaction intents
9.  Pre-physics gameplay/navigation queries and kinematic targets
10. TA-5 Physics Step
11. Normalize contacts/overlaps/triggers/projectile facts
12. Resolve movement/support/physical state
13. Resolve perception facts generated by the physical/action result
14. Resolve combat hits/damage/status intents and interaction eligibility
15. Prepare and commit owning-domain transactions/outcomes
16. Reflect committed consequences into active leased components
17. Queue AI notifications/urgent interrupts for next valid decision boundary
18. Run actor/object lifecycle transitions
19. Apply deferred runtime structural mutations
20. Apply deferred safe physics/navigation proxy mutations
21. Reach Stable Simulation Boundary
22. Publish immutable runtime/read/render/audio/debug snapshots
23. Tick End
```

## 3. AI Does Not Mutate Mid-Physics

No AI behavior, pathfinding callback, perception callback, or worker result may directly mutate:

- transform;
- physics bodies;
- Health;
- inventory;
- mission state;
- navigation topology;
- persistent domain state

from inside TA-5 or worker callbacks.

They enqueue typed facts/intents for designated phases.

## 4. Async Result Consumption

Path/navigation-support results are consumed at phase 5 only after freshness validation.

Validation includes:

- SceneGeneration;
- RuntimeEntityHandle generation;
- NavigationRevision;
- command/task generation;
- actor/profile revision;
- request sequence.

Rejected stale results produce diagnostics but no gameplay mutation.

## 5. Perception Update Timing

Perception has two bounded sources:

- observations/messages already available at tick start are ingested before decision phase;
- facts produced by current physical/action results are normalized after physics and added to memory at phase 13.

A newly observed consequence can schedule an urgent decision for the next valid AI decision boundary; AI does not rewind earlier movement/physics in the current tick.

## 6. Reaction Timing

Reaction delay is measured from the committed/normalized observation time, not from render-frame visibility.

If a target becomes visible during current tick, an actor can react only when:

- its perception model acquired the observation;
- required authored reaction delay has elapsed;
- its next valid AI action phase runs.

This makes reaction frame-rate independent.

## 7. AI Decision Phase

At phase 7, `AIScheduler` processes due actors in deterministic order.

The decision phase may:

- transition awareness state;
- choose/continue tactical goal;
- choose crew/robot task sub-action;
- request/replan path;
- select cover/work/observation candidate;
- issue typed action intents for phase 8;
- transition Blocked/Failed state when owning rules justify it.

It cannot directly commit cross-domain ownership or mission outcomes.

## 8. AI Action Intent Phase

Player and AI action intents enter the same downstream movement/combat/interaction authority.

Examples:

```text
AI chooses Fire
→ FireWeaponIntent
→ weapon validation/ammo consumption
→ TA-5 trajectory
→ Combat resolution
```

and:

```text
AI chooses Move
→ desired movement intent
→ CharacterMotor / ship/robot motion
→ actual physical result
```

AI has no alternate cheat execution path.

## 9. Perception Fact Phase

After physical facts are known, AI perception can consume:

- current validated line-of-sight result;
- semantic NoiseFacts;
- damage-source information;
- newly triggered alarm facts;
- hazard discoveries;
- shared communication messages whose delivery boundary is due.

These update knowledge only; they do not themselves fire weapons or move actors during the same already-resolved physics step.

## 10. Consequence Reflection

At phase 16 AI runtime reads the committed result of:

- Health/damage;
- ammo/resource consumption;
- door/topology change;
- repair/hack result;
- command/task state;
- communication changes.

AI never assumes its requested action succeeded before this reflection.

## 11. Urgent Interrupt Queue

Post-consequence events can enqueue typed urgent interrupts, for example:

- target defeated/lost;
- actor critically damaged;
- grenade/hazard recognized;
- command superseded;
- path/traversal invalidated;
- weapon became unusable;
- communication disconnected.

Interrupts are processed at the next valid AI phase in stable priority/order rather than executing arbitrary callbacks immediately.

## 12. Navigation Mutation Phase

Dynamic nav overlays/tile updates prepared earlier are integrated only at the deferred navigation-safe boundary in phase 20, after gameplay/topology commits and after current path-following consumers have completed.

`NavigationRevision` changes then invalidate/revalidate paths for later ticks.

## 13. Actor Activation

An actor entering ActiveLocal mode becomes AI-executable only after:

- TA-2 Activation Lease is committed;
- TA-7 components exist;
- navigation profile is valid;
- required runtime proxies are ready;
- current semantic AI state is reconstructed.

Activation does not grant a free perception scan beyond normal first scheduled sensing.

## 14. Actor Deactivation

Before leaving ActiveLocal:

- AI stops accepting new local actions;
- current semantic task/knowledge state is captured;
- active path/worker request generations are invalidated;
- leased gameplay state returns;
- logical off-screen location/task state is produced;
- runtime AI components are reclaimed in deferred cleanup.

Late worker results fail freshness checks.

## 15. Deterministic Actor Ordering

Every multi-actor AI phase uses a stable order.

Preferred key:

1. persistent typed ID raw value when actor has one;
2. stable runtime entity sort key for transient actors.

Semantic priorities can precede this key only when explicitly part of the scheduler/task rule.

## 16. Deterministic Candidate Ordering

Candidate collections such as targets, cover points, work anchors, formation slots, and search points use explicit stable keys before equal-score resolution.

Hash-map/container iteration order is never gameplay authority.

## 17. AI Randomness

Baseline AI does not require random action selection.

If authored behavior later needs bounded random variation, it must use TA-2 scoped PCG32 with a stable AI stream/scope and cannot consume a global random stream whose call count depends on render frames or worker completion.

## 18. AI Debug Snapshot

At Stable Simulation Boundary, a development-only immutable `AIDebugSnapshot` can expose selected diagnostics without granting debug state write authority.

It can include:

- actor AI mode/state;
- current command/task/goal/action;
- perception memory/confidence;
- FOV/sensor shapes;
- Last Known Positions;
- path corridor and traversal links;
- cover/work/search candidates and scores;
- blocked reason;
- current scheduler class/next update;
- async request/result revisions;
- off-screen logical route;
- decision/interrupt trace.

## 19. Debug Rendering

TA-4 development debug rendering may visualize `AIDebugSnapshot` data:

- navmesh tiles/polygons;
- 3D flight graph/cells;
- paths/corridors;
- cover/annotation points;
- perception cones/rays;
- knowledge positions/confidence;
- formation slots;
- hazard/access overlays.

Debug rendering is a consumer only.

## 20. Debug Commands

Mutating AI during development requires explicit typed debug commands entering ordinary simulation boundaries, such as:

- force replan;
- set test command;
- inject known observation;
- toggle selected navigation area for test;
- move actor through safe test teleport only in dedicated debug/test mode.

Debug widgets never hold writable component/store references.

## 21. Validation Layers

TA-8 validation has four levels:

1. **Content/Static Validation** — traversal profile/link/annotation consistency;
2. **Headless Unit/Component Tests** — path, perception, decisions, scheduling;
3. **Scenario Integration Tests** — actors in representative station/mission spaces;
4. **Runtime Diagnostics/Assertions** — stale generations, illegal authority, impossible link state, invalid AI transition.

TA-14 later turns these into final CI gates.

## 22. Navigation Content Validation

Static/runtime checks include:

- no link endpoint outside compatible navigation space;
- door/airlock link references existing target;
- Heavy links satisfy Heavy clearance/capability metadata;
- work/cover anchors project to compatible navigation;
- no duplicate stable link/annotation keys;
- free-flight cells do not overlap blocked solid space beyond defined tolerance;
- authored reinforcement/spawn anchors have valid egress where required.

## 23. AI State Validation

Development assertions check invariants such as:

- Disabled/Incapacitated actor does not issue ordinary combat movement;
- robot command target generation matches active command;
- AI target knowledge exists before knowledge-limited target selection;
- actor path profile matches actor mobility;
- off-screen actor has no live RuntimeEntityHandle;
- ActiveLocal actor with persistent leased facets has matching ActivationEpoch;
- no AI action claims committed success before owning result.

## 24. Headless Tests

Core AI/navigation tests require no OpenGL/audio device.

Representative deterministic fixtures include:

- multi-room interior with doors/airlock/lift;
- hazard reroute;
- Heavy robot narrow-route exclusion;
- cover engagement/search;
- robot command disconnect/reconnect;
- crew emergency evacuation;
- station off-screen travel;
- tile rebuild/revision invalidation.

## 25. Deterministic Replay Trace

Development tests can record a compact AI trace:

- TickIndex;
- actor ID;
- observations accepted;
- goal/action transition;
- path request/result IDs;
- blocker/result;
- command/task state.

For identical deterministic inputs/seeds, headless regression should reproduce the same semantic trace subject to explicitly versioned algorithm changes.

## 26. Failure Diagnostics

When an actor cannot progress, the system reports the most specific known blocker, for example:

- NoNavigablePath;
- SecurityDenied;
- DoorUnavailable;
- AirlockUnsafe;
- HeavyClearanceInsufficient;
- HazardProtectionMissing;
- TargetUnknown/Lost;
- CommunicationDisconnected;
- ResourceMissing;
- WorkAnchorOccupied;
- NavigationDataUnavailable;
- StaleAsyncResult.

Generic `AI failed` is insufficient for development diagnostics.

## 27. Performance Boundary

TA-8 defines schedulability and instrumentation but not final numeric budgets.

TA-13 must set budgets for:

- path jobs;
- perception queries;
- decision updates;
- active AI counts;
- nav tile rebuilds;
- off-screen actor advancement;
- debug overhead.

Correctness contracts in TA-8 cannot be disabled to meet a budget silently.

## 28. Explicit Non-Goals

No AI mutation inside physics/worker callbacks, no debug UI gameplay authority, no untracked random AI, no render-frame reaction timing, no hidden path teleport, and no generic opaque AI failure state.

## 29. Dependencies

Depends on TA-1/2/3/4/5/6/7 plus `52`–`59`.
