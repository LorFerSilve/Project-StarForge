# Star Systems

> **Status:** Draft  
> **Authority:** Strategic star-system composition, system metadata, location selection, environmental context, and authored/procedural system generation rules

## 1. Purpose

Star systems group strategically related locations into understandable exploration spaces.

## 2. System Definition

A Star System defines:

- System ID;
- name;
- sector;
- stellar/environmental class;
- major bodies;
- strategic locations;
- faction control/claims;
- resource profile;
- known routes;
- threat profile;
- historical significance.

## 3. Selective Representation

The game represents only bodies/locations with gameplay relevance.

A system may contain astronomical objects that are not individually selectable.

## 4. System Types

Baseline system archetypes include:

- inhabited core/frontier system;
- industrial/mining system;
- research system;
- contested border system;
- abandoned system;
- hazardous stellar system;
- anomalous system.

## 5. Inhabited System

Contains one or more:

- colony;
- station;
- trade facility;
- shipyard;
- defense installation.

## 6. Industrial System

Emphasizes:

- asteroid belts;
- refineries;
- cargo routes;
- mining infrastructure;
- industrial faction presence.

## 7. Research System

Can contain:

- laboratories;
- observatories;
- anomaly sites;
- restricted stations;
- scientific expeditions.

## 8. Contested System

Has overlapping faction claims and elevated conflict.

Control may vary by location rather than one universal system owner.

## 9. Abandoned System

Contains limited current population but significant:

- derelicts;
- ruins;
- automated systems;
- survivors;
- salvage.

## 10. Hazardous System

Environmental conditions can include:

- radiation;
- debris;
- stellar activity;
- navigation interference.

Hazard mechanics are owned by Missions/World environment specs.

## 11. Anomalous System

Contains Fracture-related or ancient phenomena.

Access may require Reach IV or special route knowledge.

## 12. Resource Profile

A system defines relative occurrence weights for canonical resources.

It cannot invent undefined materials.

## 13. Faction Presence

A system can contain multiple faction presences.

Examples:

- controlling faction;
- trade enclave;
- hostile outpost;
- pirate activity;
- neutral settlement.

## 14. System Discovery

A system can be known before all internal locations are discovered.

Discovering the system reveals only justified baseline information.

## 15. Procedural System Rules

Procedural systems use authored templates specifying:

- allowed location count;
- resource weights;
- faction presence;
- hazard types;
- threat range;
- route density.

## 16. Authored Story Systems

Story-critical systems have fixed IDs/names and required locations.

Procedural generation cannot remove mandatory narrative content.

## 17. No Full Orbital Simulation

System maps use strategic relative representation.

Real orbital periods/positions do not need continuous simulation.

## 18. Local Flight

Selected locations can open local flight zones.

A system map itself is not one continuous flyable volume.

## 19. Persistence

System discovery, location discovery, faction state, major site outcomes, and route state persist.

## 20. Explicit Non-Goals

Star systems do not require full astrophysical simulation, every moon/asteroid as a node, or real-time orbit propagation.

## 21. Tuneable Parameters

Tuneable values include number of strategic locations, procedural weights, and threat/resource density.

## 22. Dependencies

This specification depends on Galaxy Structure, Planets/Moons, Space Locations, Factions, Resources, Navigation, and Missions.

## 23. Open Questions

None in the star-system baseline.
